# Phase 2 read-only dependency assessment

Assessed 2026-11-09 using `npm audit --json`, `npm audit --omit=dev --json`, the lockfile and production bundle inspection. No automatic fix, unrelated upgrade, or advisory suppression was applied.

The prior Phase 1 install reported 7 findings. After the requested modular Firebase SDK and emulator tools were added, npm reports **24 affected package entries: 2 low, 16 moderate, 6 high**. The `--omit=dev` dependency graph reports **11 entries: 2 low, 4 moderate, 5 high**. These totals include parent/metavulnerability chains, not 24 independent exploit paths. The latter graph includes build tooling historically listed under dependencies; it is not a list of reachable browser vulnerabilities.

Installed direct additions: `firebase@13.2.0` (runtime), `firebase-tools@15.35.0` and `@firebase/rules-unit-testing@6.0.0` (development). Firebase Auth is the only Firebase product imported into the pilot. No Firestore, compat, gRPC, legacy Dexie, jsPDF or XLSX implementation is included in the production pilot bundle. Legacy billing stays available only in the explicit development mode.

## Limits and release considerations

This is source/dependency reachability assessment, not exploit testing or a guarantee of absence. SDK/tooling code may expose more surface if new products, endpoints, imports or untrusted build inputs are introduced. Reassess before Phase 3 business access or a release. npm proposes some major-version downgrades (for example Firebase 9.14.0, rules testing 2.0.7, CLI 13.11.2, PWA plugin 1.1.0); those are solver suggestions, not a reviewed migration plan. Preserve the supported modular SDK and investigate upstream fixes rather than applying `npm audit fix --force`.

Existing and added dependency risk remains documented and unresolved. No deployed/live application, cloud billing, service account, or production data was accessed for this assessment.
